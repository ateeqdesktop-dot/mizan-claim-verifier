# مقارنة أفكار مشاريع AI/ML

**المؤلف:** Manus AI  
**الهدف:** اختيار فكرة تجمع القيمة الواقعية والعمق التقني والأصالة وقابلية التنفيذ وقوة Portfolio.

## منهجية الاختيار

قورنت ثماني أفكار في خمسة معايير موزونة: القيمة الواقعية 25%، العمق التقني 25%، الأصالة 20%، قابلية التنفيذ 15%، وقوة Portfolio 15%. أُعطي كل معيار درجة من 1 إلى 5، ثم حُوّلت النتيجة إلى مقياس من 100. لم تُستخدم السهولة وحدها كمعيار قرار؛ بل عوقبت الأفكار التي تحتاج بيانات غير متاحة أو تكرر Benchmark ناضجًا دون مساهمة إضافية.

## المرشحون

### 1. ميزان — Arabic Evidence-Backed Claim Verification

المشكلة هي صعوبة التحقق من الادعاءات العربية بسرعة وبصورة قابلة للتفسير. يقترح المشروع نظامًا يسترجع مقالات التحقق والجمل المرتبطة ثم ينتج تصنيفًا احتماليًا مع سياسة امتناع عند عدم كفاية الدليل. يستخدم NLP عربيًا، TF-IDF للكلمات والحروف، تصنيفًا خطيًا، واسترجاعًا مستقلًا للأدلة. يعتمد على AraFacts الأساسية، التي تحتوي النسخة المحلية منها على 6,222 ادعاءً ومقالة تحقق، مع إمكانية إجراء اختبار خارجي على AuRED دون خلطه في التدريب [1] [2]. البيانات متاحة للبحث والاستخدام غير التجاري وفق شروط المصدر، ولا يحتاج النظام إلى API مدفوعة. صعوبته متوسطة إلى مرتفعة، والوقت التقديري 5–7 أسابيع. قيمته العلمية مرتفعة لأنه يختبر منع تسرب الأدلة والتقسيم الزمني والامتناع، وقيمته العملية مرتفعة لأنه يقدم Demo واضحًا. قوته في GitHub وPortfolio مرتفعة، كما يمكن تطويره لاحقًا إلى استرجاع دلالي، stance detection، ومعايرة ثقة أفضل.

### 2. درع — Multi-Signal Cyber Threat Behavior Detection

المشكلة هي أن كشف التهديدات من إشارة واحدة يسبب إنذارات كاذبة. يجمع المشروع سجلات IDS/IPS وIoT وربما خصائص البرمجيات الخبيثة لبناء تمثيل سلوكي متعدد الإشارات مع درجة مخاطرة وتفسير. يستخدم anomaly detection، خصائص تسلسلية ورسمية، ونموذجًا قابلًا للتفسير. توجد مصادر بيانات سيبرانية مفتوحة ضمن فئات IDS/IPS وIoT وMalware، لكن توحيد مخطط البيانات وشروط الاستخدام يحتاج تحققًا منفصلًا [3]. الصعوبة مرتفعة، والوقت 7–10 أسابيع. قيمته التجارية والعلمية قوية، لكن مخاطرة التنفيذ أعلى بسبب اختلاف الصيغ وصعوبة بناء Demo موحد. درجته 90/100، وهو مرشح قوي لإصدار لاحق لاختيار ميزان.

### 3. بصيرة — Industrial Defect Detection and Localization

المشكلة هي اكتشاف العيوب الصناعية قبل وصول المنتج إلى العميل. يستخدم المشروع كشف الشذوذ غير المراقب وتحديد موضع العيب بقناع بصري، اعتمادًا على MVTec AD التي تضم أكثر من 5,000 صورة عالية الدقة عبر 15 فئة مع أقنعة اختبار [4]. البيانات متاحة للاستخدام غير التجاري وفق CC BY-NC-SA 4.0، ولا يحتاج المشروع API خارجية. الصعوبة متوسطة إلى مرتفعة، والوقت 6–8 أسابيع. قيمته العملية والعرض البصري ممتازان، لكن المجال مزدحم، ولذلك يلزم تميز إضافي مثل نموذج خفيف أو تقرير ثقة قابل للتفسير. درجته 86/100.

### 4. صيانة — Uncertainty-Aware Predictive Maintenance

المشكلة هي التنبؤ بفشل المعدات قبل وقوعه مع معرفة درجة عدم اليقين. يستخدم المشروع NASA C-MAPSS للتنبؤ بالعمر التشغيلي المتبقي RUL، مع نماذج زمنية ومعايرة عدم اليقين وتفسير أثر الحساسات [5]. البيانات متاحة عبر بوابة NASA، لكن صفحة المصدر لا تثبت ترخيص إعادة توزيع واضحًا؛ لذلك يجب تجنب إعادة توزيعها داخل المستودع. الصعوبة متوسطة إلى مرتفعة، والوقت 4–6 أسابيع. القيمة العملية قوية، لكن المشروع مكرر نسبيًا على GitHub، ويتطلب مساهمة منهجية واضحة كي يكون مميزًا. درجته 86/100.

### 5. نبض — Cost-Aware Streaming Anomaly Monitor

المشكلة هي أن كل إنذار شاذ ليس متساوي التكلفة؛ فالإنذارات الكاذبة قد تكون أغلى من تأخر الإنذار. يبني المشروع كاشفًا متدفقًا يضبط العتبات وفق تكلفة الإنذار ويراقب انجراف البيانات. يمكن استخدام NAB مع بياناته ووسومه وأدوات تقييمه [6]. البيانات والكود مفتوحان بحسب المصدر، ولا يحتاج المشروع API مدفوعة. الصعوبة متوسطة، والوقت 4–6 أسابيع. قوته العلمية في القرار الواعي بالتكلفة، لكن Benchmark ناضج والمشاريع حوله كثيرة، لذلك يحتاج Demo streaming حقيقيًا. درجته 85/100.

### 6. طاقة — Energy Demand Forecasting with Anomaly Detection

المشكلة هي التنبؤ بالطلب أو التوليد مع اكتشاف القراءات الشاذة. يستخدم المشروع نماذج سلاسل زمنية واحتمالات تنبؤ وخصائص خارجية مثل الطقس أو التقويم. توفر بوابات DOE وEIA وOEDI بيانات طاقة مفتوحة متعددة [7]. توفر البيانات مجاني أو مفتوح بحسب المجموعة المختارة، ولا يلزم API مدفوعة إذا نُزلت نسخة ثابتة. الصعوبة متوسطة، والوقت 4–6 أسابيع. القيمة التجارية جيدة، لكن تعريف المتغيرات واختيار مصدر مستقر يضيفان مخاطرة. درجته 81/100.

### 7. مرآة — Arabic Fake News Detector

المشكلة هي تصنيف الأخبار العربية إلى حقيقية أو زائفة. يستخدم المشروع AraBERT أو CAMeLBERT مع موازنة الفئات وتفسير الكلمات المؤثرة. توجد مجموعات عربية حقيقية وأبحاث حديثة في كشف الأخبار الزائفة [8]. البيانات البحثية متاحة وفق كل مصدر، ولا يحتاج النظام API مدفوعة. الصعوبة منخفضة إلى متوسطة، والوقت 3–5 أسابيع. القيمة العملية معقولة، لكن المشروع مكرر جدًا إذا اقتصر على real/fake؛ لذلك لا يضاهي ميزان دون طبقة أدلة أو تفسير أو تقييم خارج المجال. درجته 79/100.

### 8. مسار — Arabic Learning Resource and Skill-Gap Recommender

المشكلة هي مساعدة المتعلم العربي على اختيار موارد مناسبة لسد فجوة مهارية. يستخدم المشروع توصية هجينة، ontology للمهارات، معالجة مشكلة cold-start، ومقاييس ranking. التحدي الأكبر هو الحصول على بيانات تفاعل حقيقية ومرخصة؛ لا يكفي توليد بيانات اصطناعية لإثبات جودة التوصية. الصعوبة متوسطة إلى مرتفعة، والوقت 6–8 أسابيع. القيمة العملية جيدة، لكن التنفيذ الفوري غير مناسب دون Dataset مرخصة مستقرة. درجته 77/100.

## القرار

اختير **ميزان** لأنه يحقق أفضل توازن بين Real Value وTechnical Quality وInnovation وReliability وDocumentation. لا يكتفي بتصنيف نص عربي، بل يعرض مسارًا قابلًا للمراجعة من الادعاء إلى المرشح الدليلي إلى قرار احتمالي أو امتناع صريح. هذا القرار مدعوم ببيانات عربية منشورة وبفجوة بحثية موثقة في التحقق العربي القائم على الأدلة [1] [2].
