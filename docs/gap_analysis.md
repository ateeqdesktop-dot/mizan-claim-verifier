# تدقيق الفجوات — Mizan

## الخلاصة التنفيذية

المشروع الحالي ليس نموذجًا شكليًا؛ فهو يحتوي على خط بيانات حقيقي، نموذج تصنيف متعدد الفئات، مسترجع أدلة، خدمة امتناع، واجهة FastAPI، اختبارات، رسوم تقييم، وتوثيق أولي. لذلك لا تحتاج النسخة الجديدة إلى تغيير الفكرة الأساسية. القرار الأفضل وفق أولوية **القيمة الواقعية ثم الجودة التقنية ثم الاعتمادية** هو ترقية ميزان إلى نسخة Portfolio قابلة للعرض، بدل هدم نظام يعمل وإعادة بناء مشروع مختلف أقل نضجًا.

| 2 | لا توجد CI | لا يوجد تحقق تلقائي عند كل تغيير | إضافة GitHub Actions لتثبيت الحزمة وتشغيل الاختبارات وcompileall وgit diff --check |

| 4 | اختبارات الحالات السلبية محدودة | قد لا تظهر مشاكل التحقق أو الامتناع أو غياب النموذج | إضافة اختبارات validation، missing artifacts، abstention، metadata، وAPI errors |
| 5 | لا توجد مقارنة baseline واضحة في التنفيذ | المتطلب البحثي يطلب مقارنة نماذج مناسبة | إضافة Majority baseline وLinearSVC/Logistic variant داخل تقرير قابل لإعادة التشغيل دون تغيير النموذج التشغيلي قبل إثبات التفوق |

| 7 | لا توجد صفحة Model Card أو تقرير قرار | يصعب تقييم حدود النموذج واستعماله المسؤول | إضافة `docs/model_card.md` وملخص نتائج يوضح الفئات النادرة وعدم استخدامه للحكم الرسمي |
| 8 | لا يوجد ملف بيئة/إعدادات واضح للواجهة | تجربة التشغيل تحتاج خطوات أكثر | إضافة `.env.example` اختياريًا، مع إبقاء الإعدادات الآمنة الافتراضية وعدم إدخال أسرار |
| 9 | لا يوجد فحص أمني تلقائي | قد تمر أسرار أو ملفات كبيرة دون تنبيه | إضافة فحص secrets بسيط و`pip-audit` اختياري في CI دون تعطيل التشغيل المحلي |

## قرار النطاق

لن نضيف قاعدة بيانات أو مصادقة أو اتصالًا حيًا بمصادر ويب في هذه النسخة؛ لا تحتاج مهمة التحقق القابلة لإعادة الإنتاج هذه المكونات، وإضافتها ستزيد سطح الهجوم والتعقيد دون قيمة تناسب الهدف. ستكون الواجهة المحلية طبقة عرض رقيقة فوق API الحالي، بينما يبقى النموذج وخط التقييم مستقلين وقابلين للاختبار.

## معايير القبول للنسخة المحسنة

1. يمكن تشغيل Demo محليًا بأمر واحد بعد وجود artifacts، ويعرض حالات النجاح والامتناع والخطأ بصورة مفهومة.
2. تستمر اختبارات النموذج وAPI، وتضاف حالات حواف بحيث لا يقل عدد الاختبارات عن النسخة الحالية.
3. ينجح GitHub Actions في بيئة نظيفة دون بيانات خام أو أسرار.
4. تتضمن وثائق المشروع مقارنة baseline وModel Card وقيود البيانات والترخيص.
5. يبقى القرار النهائي محافظًا: لا يعرض `verdict` قطعيًا عند غياب دليل كافٍ.
6. لا تُرفع البيانات الخام أو مفاتيح API أو ملفات النماذج الكبيرة إلى GitHub.

## التغييرات المؤجلة عمدًا

الاسترجاع الدلالي العربي وreranker وstance classifier تحسينات بحثية قيّمة، لكنها تحتاج بيانات أزواج evidence/stance موثوقة وضبطًا مستقلًا. لن ندخلها في النسخة المحسنة كادعاء غير مثبت؛ ستبقى ضمن خطة التطوير المستقبلية مع إبقاء baseline الحالي شفافًا وقابلًا لإعادة الإنتاج.
