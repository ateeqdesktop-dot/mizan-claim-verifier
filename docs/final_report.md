**المؤلف:** Manus AI

**التاريخ:** 2026-08-12

**المستودع:** [ateeqdesktop-dot/mizan-claim-verifier](https://github.com/ateeqdesktop-dot/mizan-claim-verifier)

## الملخص التنفيذي

**ميزان** نظام عربي قابل للتشغيل للتحقق من الادعاءات بالأدلة. لا يقتصر على تصنيف نصي ثنائي، بل يفصل المهمة إلى ثلاثة مكونات قابلة للفحص: مصنف احتمالي متعدد الفئات، ومسترجع مستقل لمقالات التحقق، وسياسة امتناع تمنع إصدار `verdict` نهائي عندما لا تتوافر صلة دليل أو ثقة كافية. اختيرت الفكرة لأنها تجمع بين قيمة عملية مباشرة، وبيانات عربية حقيقية، ونموذج ML يمكن تدريبه وتقييمه محليًا دون الاعتماد على واجهة ChatGPT أو خدمة خارجية لحظة الطلب.

## المشكلة والحل

تواجه أنظمة كشف الأخبار الزائفة ثلاثة مخاطر واضحة: التعلم من إشارات المصدر أو الزمن بدل مضمون الادعاء، إصدار حكم غير قابل للمراجعة، والتأثر الشديد بعدم توازن الفئات. يعالج ميزان هذه المخاطر بخط معالجة عربي محافظ، واسترجاع TF-IDF مستقل لمقالات التحقق، وترتيب للجمل الأقرب إلى الادعاء، ثم إرجاع JSON يوضح الحكم الاحتمالي والدليل والمرشحين ودرجة التشابه. إذا لم يتجاوز الدليل أو الثقة العتبات المحددة، يعيد النظام `insufficient_evidence` بدل تحويل التخمين إلى حكم قطعي.

## الذكاء الاصطناعي والبيانات

يستخدم المصنف FeatureUnion يجمع TF-IDF للكلمات والحروف مع Logistic Regression موزون للفئات (`class_weight=balanced`). ويستخدم المسترجع TF-IDF وقياس cosine similarity لفهرسة مقالات التحقق وترتيبها. مسار الخدمة تشغيليًا **claim-only**؛ أما المسار evidence-conditioned فيُستخدم كاختبار تشخيصي يقارن أثر الدليل المعروف أو المسترجع. لا توجد معايرة احتمالات مستقلة أو stance classifier في هذه النسخة، ولا تُعرض هذه المكونات بوصفها منفذة.

تُبنى النسخة الأساسية على AraFacts، وهي مجموعة عربية من الادعاءات الطبيعية التي تصفها الورقة الأكاديمية الأصلية بأنها تضم 6,121 ادعاءً من خمسة مواقع للتحقق من الحقائق [1]. بعد الدمج وإزالة التكرار في الملفات المحلية المتاحة، استُخدم 6,221 سجلًا صالحًا للتدريب النهائي. حُفظت البيانات الخام خارج Git بسبب شروط المصدر وحجمها، وتوثق [مذكرة تدقيق المصادر](research_audit_notes.md) سبب إبقاء AuRED اختبارًا خارجيًا مؤجلًا بدل خلط مهمته المختلفة مع AraFacts [3].

| العنصر | التنفيذ الفعلي |
|---|---|
| التطبيع | NFKC، إزالة التشكيل والمد والروابط، وتوحيد أشكال الحروف العربية |
| الفئات | `False`, `Partly-false`, `True`, `Sarcasm`, `Unverifiable` |
| المصنف | word + character TF-IDF مع Logistic Regression موزون |
| الاسترجاع | TF-IDF cosine similarity على مقالات التحقق |
| الأدلة | ترتيب جمل المقال الأعلى صلة بالادعاء |
| سياسة الامتناع | `min_retrieval_score=0.05` و`min_confidence=0.45` |
| البيانات الخام والنماذج | محلية فقط؛ لا تُرفع إلى المستودع العام |

## بروتوكول التقييم والنتائج

أُجري تقييم زمني 70/15/15 لمحاكاة الانتقال إلى ادعاءات أحدث، وتقييم طبقي 80/20 للمقارنة داخل التوزيع. يتضمن خط التدريب ثلاثة سيناريوهات: claim-only، وoracle evidence، وretrieved evidence. كما يقارن benchmark بين Majority وLinearSVC وLogistic Regression. لأن فئة `Unverifiable` لا تظهر في فترة الاختبار الزمني، لا يجوز تفسير نتيجة ذلك البروتوكول على أنها قياس متوازن لقدرة النظام على كل الفئات.

| البروتوكول | Accuracy | Macro-F1 | Balanced Accuracy |
|---|---:|---:|---:|
| زمني — claim-only | 0.642 | 0.261 | 0.330 |
| طبقي — claim-only | 0.681 | 0.301 | 0.295 |
| Majority — زمني | 0.549 | 0.142 | — |
| مطابقة ملصق أعلى مرشح — زمني | — | — | 0.510 |
| مطابقة ملصق أعلى مرشح — طبقي | — | — | 0.592 |

هذه النتائج توضح أن النموذج يتجاوز خط الأساس في الدقة وMacro-F1 في البروتوكول الزمني، لكنها لا تثبت صحة الادعاء ولا صلاحية النظام لاتخاذ قرارات عالية المخاطر. تُحفظ المقاييس التفصيلية ومصفوفات الالتباس والتنبؤات في `artifacts/metrics.json` والملفات التابعة له.

## التنفيذ والواجهة

يتضمن المشروع حزمة Python منظمة، وسكربت تدريب وتقييم، وCLI للتنبؤ الفردي، وFastAPI، وواجهة Demo عربية RTL متجاوبة. توفر الخدمة المسارات `/health` و`/metadata` و`/verify` و`/demo`. في فحص تشغيل فعلي باستخدام artifacts محلية، أعاد `/health` حالة `ok`، وأعاد `/demo` صفحة HTML عربية بحجم 5,879 بايت، وأعاد `/verify` استجابة HTTP 200. وتثبت اختبارات الخدمة أن النظام يحافظ على `model_verdict` الداخلي لكنه يعيد `verdict: null` و`evidence_status: insufficient_evidence` عند تجاوز عتبة الامتناع؛ وهذا يثبت سلوك الامتناع المقصود دون ادعاء معايرة احتمالية مستقلة.

## الجودة والأمان وقابلية التتبع

## إعادة الإنتاج

بعد تنزيل AraFacts من مستودعه الرسمي [2] ووضع الملفين في `data/AraFacts.csv` و`data/AraFacts_content.csv`، يمكن إعادة بناء المشروع بالأوامر التالية:

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -e ".[dev]"
make train CLAIMS=data/AraFacts.csv CONTENT=data/AraFacts_content.csv
make benchmark CLAIMS=data/AraFacts.csv CONTENT=data/AraFacts_content.csv
make check
make api
```

بعد تشغيل `make api` تُفتح الواجهة على `http://localhost:8000/demo`. يمكن أيضًا تشغيل Docker بعد توفر artifacts المحلية باستخدام `docker build -t mizan-claim-verifier .` ثم `docker run -p 8000:8000 mizan-claim-verifier`.

## الحدود والعمل المستقبلي

الاسترجاع الحالي lexical، ولذلك قد يختار مقالًا متشابهًا في الكلمات لكنه لا يعالج الادعاء نفسه. كما أن مصدر البيانات ليس عينة عشوائية من كل الخطاب العربي، والفئات النادرة قليلة جدًا، ولا يجلب النظام صفحات ويب جديدة لحظة الطلب. التحسين الأعلى قيمة هو إضافة استرجاع دلالي عربي وreranker مدرب على أزواج claim/evidence، ثم stance detection وضبط عتبات الامتناع على validation set. بعد ذلك يمكن إجراء اختبار نقل مستقل على AuRED، مع حساب Recall@k وMRR ومعايرة الاحتمالات، بشرط تنفيذ كل تجربة وتوثيق بياناتها قبل نشر نتائجها.

## قيمة المشروع في Portfolio

يمثل ميزان مشروع AI/ML حقيقيًا قابلًا للمناقشة أمام لجنة أكاديمية أو صاحب عمل: فيه قرار بحثي موثق، بيانات عربية موثقة، معالجة NLP حقيقية، نموذج قابل للحفظ، استرجاع أدلة، سياسة سلامة، تقييم متعدد البروتوكولات، benchmark، API، Demo، اختبارات، CI، سجل Git منظم، وقيود معلنة بوضوح. القيمة الأساسية ليست ادعاء الوصول إلى نموذج مثالي، بل إظهار دورة ML كاملة يمكن مراجعتها وإعادة تشغيلها وتحسينها دون إخفاء نقاط الضعف.
